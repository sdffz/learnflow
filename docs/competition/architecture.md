# 系统架构说明

## 设计目标

Architecture 以可解释、可离线演示和失败隔离为优先目标。系统不让单个大模型调用承担全部流程，而是把画像、课程分析、资源生成、质检与反馈拆成有清晰输入输出的角色。

## 多智能体协作

一次资源运行的公开事件顺序：

1. `orchestrator` 读取画像并拆分任务。
2. `curriculum` 定位课程与知识依赖。
3. `resource_planner` 确定资源组合。
4. 六个资源角色分别产出并经历运行、完成或失败状态。
5. `review` 汇总内容质量与安全复核。
6. `orchestrator` 写入最终 `completed` 或 `partial`。

每个事件持久化到 SQLite，SSE 先重放已经保存的事件，再推送实时事件。因此页面刷新或客户端晚连接不会丢失完整进度。

## 个性化数据流

```text
学生自然语言
  → 维度抽取 + 证据 + 置信度
  → 资源难度/媒介/推荐理由
  → 路径重排
  → 练习与评估掌握度
  → 画像更新与下一轮推荐
```

## 个人知识数据流

```text
用户创建知识文件夹
  → 文件 / 手机照片 / 快速笔记
  → 私有文件存储
  → 文本提取或 OCR
  → 摘要、标签与知识片段
  → 课程详情和全局搜索
  → 可追溯资料详情
```

检索和存储均以数据库资料 ID 解析文件路径，原始文件只保存在私有部署的数据目录。示例课程使用独立种子标记，避免重复导入。

## 学习通连接数据流

```text
知序登录用户
  → 一次性学习通二维码（5 分钟）
  → 学习通 App 扫码确认
  → AES-GCM 加密短期 Cookie 会话（最多 24 小时）
  → 课程/文件预览（不下载视频）
  → 用户选择课程与文件夹映射
  → 持久化后台任务（下载、校验、提取、去重）
  → 个人知识库和来源追溯
```

学习通连接器只接受白名单 HTTPS 域名和逐跳重定向校验。ZIP 备用入口不依赖学习通会话，但仍使用相同的预览、映射和知识提取流程。

## 身份与租户

- 密码使用带随机盐的 `scrypt` 派生，数据库只保存派生结果。
- 登录后颁发高熵 opaque session token，数据库仅保存 SHA-256 哈希。
- Cookie 使用 `HttpOnly`、`SameSite=Lax`，HTTPS 下自动启用 `Secure`。
- 业务请求不接受客户端指定工作空间；工作空间由服务端会话推导。
- 跨站写请求会被 Origin 校验拒绝；登录、注册和 API 分别限流。
- 登录、资料、课程、运行和评估等关键操作写入审计表。

资源生成时，用户选择的课程会先在个人知识片段中检索主题相关内容；没有主题命中时使用该课程最近的知识片段。资源智能体收到的结构化上下文包含课程、资料标题、知识点和片段摘要，生成结果的元数据与界面会展示这些来源。

## 防幻觉设计

- 先对问题做安全过滤。
- 从 Markdown 课程库检索段落。
- 使用问题框架去除“什么是”等噪声。
- 对否定前缀进行短语边界校正，避免把“无监督学习”当作“监督学习”。
- 低分结果不进入上下文。
- 证据必须达到最高相关分的阈值后才进入答案。
- 无结果与提示注入直接拒答。
- 回答来源从真实检索结果派生。

## 错误处理

- 模型密钥缺失：自动使用 Mock 模式并在 UI 标注“演示模型”。
- 单资源失败：运行标记为 `partial`，成功资源仍可查看和下载。
- 后台任务异常：写入失败事件并更新运行状态。
- HTML 资源：后端先转义用户主题，前端再置于无同源权限的 sandbox iframe。
- API 无学习者或资源：返回 404，不返回伪造对象。

## 数据与隐私

- 演示角色全部为虚构数据。
- 个人资料和原始上传文件只保存在私有部署的 `LEARNFLOW_DATA_DIR`，不进入 Git、公共知识库或模型训练。
- 学习通会话密文与临时 ZIP 位于私有数据目录；断开连接或任务终态后立即清理。
- 当前为单用户演示工作空间；正式多用户隔离需要认证与管理端配合。
- SQLite 运行数据位于 `backend/data/runtime/`，已被 Git 忽略。
- 模型密钥仅通过后端环境变量读取。
- SQLite 启用 WAL、`busy_timeout` 和完整性检查后的每日自动备份。
