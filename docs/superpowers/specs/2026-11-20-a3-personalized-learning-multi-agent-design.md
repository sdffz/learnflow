# 知序 LearnFlow：个性化资源生成与学习多智能体系统设计规格

日期：2026-11-20  
状态：待用户复核  
赛题蓝本：第十五届“中国软件杯”A3  
第一版课程：《人工智能导论》

## 1. 产品目标

知序 LearnFlow 是一个面向高校学生的个性化学习 Web 应用。系统通过自然语言了解学生的学习基础、目标、薄弱点和偏好，维护至少六个维度的动态画像，并由不同职责的智能体协作生成多类学习资源、规划学习路径、提供有依据的辅导和前后测评估。

产品必须证明个性化不是界面文案，而是可观察的差异：

1. 同一知识点下，基础薄弱型、项目实践型、考试导向型学生会得到不同难度、媒介和顺序的资源组合。
2. 学生在练习、辅导或评估中产生的新证据会更新画像，并影响后续路径。
3. 所有课程回答优先来自内置知识库；依据不足时明确说明，不虚构来源。
4. 即使没有真实大模型密钥，系统也能通过确定性 Mock 模式完整演示。

## 2. 第一版范围

### 2.1 核心功能

- 对话式学习画像：自然语言抽取不少于六个维度，展示证据、置信度和更新时间，支持随学随新。
- 多智能体编排：显式编排、画像、课程分析、资源生成、内容质检、路径规划、辅导和评估角色；记录每个角色的状态、输入摘要和输出摘要。
- 六类资源：课程讲解文档、知识思维导图、分层练习、代码实操案例、演示幻灯片、动画微课。至少五类可实际生成和查看。
- 学习路径：按知识点依赖、画像和目标生成阶段化路径，并为每个节点关联资源。
- 个性化推送：资源排序考虑画像、学习进度和最近评估结果，显示推荐原因。
- 智能辅导：知识库检索、引用来源、低置信度拒答、敏感内容拦截和多轮对话。
- 学习评估：课前诊断和课后测验，按知识点统计掌握度、提升值和需要复习的内容。
- 生成体验：流式阶段进度、单个资源失败隔离、运行记录和可下载成果。
- 演示数据：内置三类虚拟学生，避免使用真实个人数据。

### 2.2 第一版不包含

- 不接入真实学校教务系统或学习管理系统。
- 不实现生产级多租户、支付、社交、教师排课和家长端。
- 不训练专用大模型。
- 不承诺实时生成高成本长视频；动画微课以浏览器可播放的 HTML/SVG 动画交付。
- 不把公开参赛仓库中的实现代码复制到本项目。

## 3. 用户与场景

### 3.1 主要用户

全日制高校学生，尤其是首次学习《人工智能导论》的本科生。第一版支持三个演示角色：

- 入门型：编程基础一般，需要概念讲解、可视化和生活类比。
- 考试型：有明确章节测验目标，需要知识清单、易错题和复习节奏。
- 项目型：已掌握基础，需要代码实操、实验步骤和拓展项目。

### 3.2 核心流程

1. 学生选择演示角色或开始自然语言访谈。
2. 系统在对话中抽取并可视化六维以上画像。
3. 学生选择课程目标和知识点，启动资源生成。
4. 编排智能体生成计划，调度多个资源智能体和质检智能体。
5. 学生查看资源、路径和推荐理由，提出问题或完成练习。
6. 评估智能体更新掌握度，画像与下一阶段路径随之调整。

## 4. 技术方案比较与选择

### 方案 A：React + FastAPI + 自研轻量状态图（采用）

- 优点：前后端职责清楚；Python 便于 RAG、内容生成和测试；自研状态图可完全离线、可追踪、依赖少。
- 代价：需要自己维护编排、重试和事件模型。
- 结论：适合比赛对稳定性、可解释性和离线演示的要求。

### 方案 B：Next.js 全栈 + LangGraph.js

- 优点：单一语言和单仓库，部署简单。
- 代价：文档生成、评估和 Python AI 生态的可选空间较小。
- 结论：适合擅长 TypeScript 的团队，不作为第一版基线。

### 方案 C：Streamlit/Gradio 原型

- 优点：开发最快。
- 代价：产品交互、资源卡片化、SSE 进度和工程质量难以达到赛题要求。
- 结论：仅适合早期验证，不作为提交作品。

## 5. 总体架构

```text
React Web UI
  │ REST + SSE
  ▼
FastAPI API Layer
  ├─ Learning Repository (SQLite)
  ├─ LearningGraph Orchestrator
  │   ├─ ProfileAgent
  │   ├─ CurriculumAgent
  │   ├─ ResourcePlannerAgent
  │   ├─ DocumentAgent
  │   ├─ MindMapAgent
  │   ├─ QuizAgent
  │   ├─ CodeLabAgent
  │   ├─ SlideAgent
  │   ├─ AnimationAgent
  │   ├─ ReviewAgent
  │   ├─ PathAgent
  │   ├─ TutorAgent
  │   └─ AssessmentAgent
  ├─ RAG Service + Knowledge Base
  ├─ Safety Service
  └─ Model Gateway
      ├─ MockProvider（默认）
      └─ OpenAI-compatible/讯飞 Provider（可选）
```

### 5.1 前端

- React + TypeScript + Vite。
- 页面包括学习首页、画像访谈、资源工作室、学习路径、智能辅导和效果评估。
- 使用原生 CSS 设计系统，支持响应式布局、清晰的信息层级和统一状态反馈。
- 资源使用标签页或卡片展示，支持 Markdown、代码高亮、公式、思维导图和动画预览。
- 创建运行后，通过 Fetch ReadableStream 消费 SSE 事件；服务端先重放已持久化事件，再推送实时事件，避免刷新后丢失进度。

### 5.2 后端

- FastAPI + Pydantic。
- SQLite 持久化学习者、画像、生成运行、资源、路径、对话和评估。
- 自研 `LearningGraph` 状态图通过明确契约调用 Agent，并发出可重放事件。
- 每个 Agent 接收结构化上下文，返回 `AgentResult`；不允许直接操作其他 Agent 的内部状态。
- 生成任务按资源隔离：单个智能体失败时返回该资源错误，其他资源继续完成。

### 5.3 模型网关

- `MockProvider`：根据画像、课程和资源类型返回稳定、可测试的结构化结果。
- `OpenAICompatibleProvider`：通过 Base URL、API Key 和模型名接入讯飞星火兼容接口或其他合规模型。
- 模型密钥仅保存在后端环境变量，不进入前端、数据库、日志或仓库。
- 无密钥时明确显示“演示模型”，不伪装成真实大模型推理。

### 5.4 检索与防幻觉

- 知识库按课程、章节、知识点和段落切块，保存来源、标题和版本。
- 第一版采用无需下载向量模型的中文 n-gram/关键词混合检索，后续可替换为向量检索。
- 检索结果必须达到阈值才可进入答案上下文。
- 回答带知识库来源；无足够证据时返回拒答说明和建议查询的知识点。
- 质检智能体检查引用、敏感内容、结构完整性、课程范围和难度匹配。

## 6. 核心数据模型

- `Learner`：姓名或演示角色、课程 ID、创建时间。
- `LearnerProfile`：维度、值、证据、置信度、更新时间。
- `GenerationRun`：目标、状态、进度、创建时间、完成时间。
- `AgentEvent`：运行 ID、Agent、阶段、状态、公开摘要、时间。
- `LearningResource`：类型、标题、知识点、内容、元数据、状态。
- `LearningPath`：阶段、节点、依赖、关联资源、推荐原因。
- `TutorMessage`：问题、答案、引用、拒答原因、时间。
- `Assessment`：阶段、逐题结果、知识点得分、提升值。

画像第一版固定至少包含：

1. 先修知识
2. 学习目标
3. 认知风格
4. 当前薄弱点
5. 资源偏好
6. 学习节奏
7. 编程基础
8. 兴趣方向

## 7. API 边界

- `GET /api/health`：服务和模型模式状态。
- `GET /api/personas`：三类演示学习者及课程信息。
- `POST /api/learners`：创建学习者。
- `POST /api/learners/{id}/profile/chat`：提交访谈消息并返回更新后的画像。
- `GET /api/learners/{id}/profile`：读取画像。
- `POST /api/learners/{id}/runs`：创建资源生成运行。
- `GET /api/runs/{run_id}/stream`：读取可重放的 SSE 阶段和结果事件。
- `GET /api/runs/{run_id}`：读取运行与资源快照。
- `GET /api/resources/{id}`：读取资源。
- `GET /api/resources/{id}/download`：下载资源。
- `POST /api/learners/{id}/paths`：生成或刷新学习路径。
- `POST /api/learners/{id}/tutor`：检索增强辅导。
- `POST /api/learners/{id}/assessments`：提交测验并更新掌握度。

## 8. 异常与边界处理

- 画像维度不足时继续访谈，不强行生成最终路径。
- 模型超时：记录错误并提供重试；Mock 模式仍可完成端到端演示。
- 单个资源失败：运行标记为部分成功，保留已成功资源。
- 知识库无匹配：辅导拒答，不输出伪造引用。
- HTML/动画资源：后端转义用户文本，前端使用受控沙箱渲染。
- 上传和下载：限制文件类型与大小；不执行用户上传的代码。
- 评估提交：校验题目属于当前课程，分数由后端计算。

## 9. 测试策略

采用测试先行：

1. 单元测试画像抽取：六维以上、重复消息更新、低信息输入不清空旧画像。
2. 单元测试编排：角色顺序、事件完整、单资源失败隔离。
3. 单元测试资源：六类资源结构有效，至少五类可下载。
4. 单元测试路径：不同画像产生不同顺序和推荐原因。
5. 单元测试 RAG：命中答案有来源，低分问题拒答，提示注入不越过证据约束。
6. 单元测试评估：分数计算、知识点更新和后续推荐变化。
7. API 集成测试：完整学习者流程从创建到资源下载。
8. 前端组件与构建检查：关键页面可渲染，生成事件能推进状态。
9. 端到端冒烟：访谈、生成、查看资源、辅导、评估五条主路径。
10. AI 质量评测：至少 20 条课程问答和拒答样本，记录可溯源率与正确拒答率。

## 10. 验收标准

- 在无 API Key、无 Docker 的普通开发环境中，用一条命令启动前后端并完成演示。
- 画像包含至少六个可见维度，且对话后可以更新。
- 一次运行至少产出一个文档、一个思维导图、一组练习、一个代码案例、一组幻灯片和一个动画微课。
- 三位演示角色在同一知识点上的资源难度、媒介或推荐理由至少有两项明显不同。
- 生成过程可看到 Agent 阶段和进度；单个资源失败不会清空已完成结果。
- 辅导答案展示引用；无依据问题必须拒答。
- 评估后画像或路径能够显示更新。
- 后端测试、前端构建和主流程端到端检查通过。
- README、需求说明、架构说明、测试报告、部署手册和 AI 工具使用说明齐全。

## 11. 交付路径

整体工作拆成三个独立交付物：

1. 核心应用：本规格覆盖的 Web 系统、课程知识库、自动化测试和运行文档。
2. 参赛文档包：需求分析、技术设计、测试报告、部署说明、AI Coding 使用说明、开源许可清单。
3. 展示包：比赛 PPT、7 分钟视频脚本、截图、演示数据和提交清单。

首先完成第 1 项；通过验收后再生成第 2、3 项，避免展示材料先于真实功能。

## 12. 发布与安全约束

- `.env`、密钥、真实学生数据和生成缓存不提交到仓库。
- 使用第三方代码或素材时记录许可证。
- 正式参赛版本在对应赛期形成，不提前把同一作品投递其他赛事或公开展示获奖。
- 提交包必须包含可执行入口、源码、课程数据、模型配置模板、文档、PPT、演示视频和 AI 工具说明。
