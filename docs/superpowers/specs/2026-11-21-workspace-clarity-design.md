# 知序 LearnFlow 自由学习工作台逻辑重构规格

日期：2026-11-21  
状态：待用户复核  
涉及范围：学生端前端信息架构、学习状态持久化、页面跳转与测试

## 1. 目标

解决当前六个功能页面彼此割裂、用户看不到学习进度和下一步操作的问题。保留自由侧边导航，不改成强制线性向导，但让用户在任何页面都能回答三个问题：

1. 我当前在学什么？
2. 我已经完成了哪些环节？
3. 我下一步最合理做什么？

## 2. 现状问题

- 选择学生后没有全局学习概览，首页仍只显示学生选择。
- 当前主题只存在于资源工作室，路径、辅导和评估页面缺少共同上下文。
- 资源生成完成后没有明确的路径入口。
- 路径生成后没有辅导或评估入口。
- 评估完成后没有回到工作台或继续学习的引导。
- 刷新页面会丢失资源运行、路径和最近评估的界面状态。
- “切换演示学生”同时承担切换和重置，缺少清晰说明。

## 3. 方案选择

采用“全局学习状态栏 + 动态首页 + 页面下一步操作”：

- 保留全部现有侧边导航。
- 在页面标题下方持续展示课程、主题、完成状态和下一步。
- 首页根据是否已有学习者显示选人页或学习工作台。
- 每个功能页面在完成核心动作后更新全局状态。
- 所有跳转保持自由，不阻止用户跨步骤访问。

不采用仅优化首页或增加强制线性步骤导航的方案。

## 4. 工作台状态

新增前端 `WorkspaceState`：

```ts
interface WorkspaceState {
  courseId: "ai-intro";
  activeTopic: string;
  latestRunId: string | null;
  latestRunStatus: "idle" | "queued" | "running" | "completed" | "partial" | "failed";
  resourceCount: number;
  pathGenerated: boolean;
  lastAssessmentScore: number | null;
  lastAssessmentAt: string | null;
}
```

默认值：

- `courseId = "ai-intro"`。
- `activeTopic = "神经网络"`。
- 其余运行状态为 idle、无运行 ID、资源数为 0、路径未生成、无评估。

状态保存在 `localStorage.learnflow_workspace`。切换或重置学生会删除学习者状态与工作台状态，避免跨学生污染。

## 5. 全局页面结构

已有学习者时，页面标题下增加统一的工作台状态区：

```text
人工智能导论 · 神经网络                    演示模型
[画像已完成] [资源 6/6] [路径已生成] [最近评估 100]
下一步：开始有依据的智能辅导                         [进入]
```

### 5.1 状态胶囊

- 画像：维度不少于 6 时显示“画像已完成”，否则显示“完善学习画像”。
- 资源：资源数为 0 时显示“尚未生成资源”；大于 0 时显示“资源 N/6”；partial 时增加“部分完成”。
- 路径：`pathGenerated` 为 false 时显示“规划学习路径”，否则显示“路径已生成”。
- 评估：无结果时显示“尚未评估”，有结果时显示“最近评估 N”。
- 每个状态胶囊可点击进入对应页面。

### 5.2 下一步推导

按以下顺序推导唯一主操作：

1. 无学习者：选择演示学生。
2. 画像不足 6 维：完善学习画像。
3. 无资源运行：生成个性化资源。
4. 运行 queued/running：恢复生成进度。
5. 资源运行 failed：重试资源生成。
6. 资源完成或部分完成但路径未生成：查看学习路径。
7. 路径已生成但未评估：完成学习评估。
8. 已有评估：进入智能辅导继续学习。

下一步操作始终显示原因，例如“六类资源已生成，接下来规划学习顺序”。

## 6. 动态首页

### 6.1 无学习者

保持现有三张演示学生卡和产品介绍。

### 6.2 已有学习者

首页改为学习工作台：

- 顶部问候与学生身份。
- 当前课程、主题、目标和薄弱点。
- 五项闭环状态。
- 最近资源完成度、路径状态和最近评估得分。
- 主按钮“继续学习”，跳转到推导出的下一步。
- 次级按钮“查看学习路径”和“切换演示学生”。

首页不再显示其他演示学生卡，避免用户误以为当前会话丢失。

## 7. 页面联动

### 画像页

- 更新画像后仍调用全局画像更新。
- 维度达到 6 个后增加“用画像生成资源”按钮。
- 跳转时保留当前主题。

### 资源工作室

- 主题选择写入 `activeTopic`。
- 创建运行后写入 `latestRunId`、`latestRunStatus`。
- SSE 完成或 partial 时写入资源数量。
- 刷新后若存在 `latestRunId`，自动读取运行快照并恢复资源和事件。
- 完成后显示“查看学习路径”和“进入智能辅导”两个动作。
- 失败时保留错误状态和重试按钮。

### 学习路径

- 成功获得路径后设置 `pathGenerated=true`。
- 页面加载时若已存在当前学习者，可直接重新获取确定性路径。
- 当前节点旁提供“查看匹配资源”。
- 页面底部提供“完成学习评估”按钮。

### 智能辅导

- 标题区显示当前主题。
- 建议问题继续可用。
- 回答失败时显示错误并保留问题。
- 页面提供“完成学习评估”操作。

### 效果评估

- 提交成功写入评估得分和完成时间。
- 结果页显示“下一步推荐”。
- “再测一次”只重置当前答题状态，不清理全局评估记录，待新结果产生后覆盖。
- 提供“返回学习工作台”。

## 8. 状态恢复

- App 初始化时同时读取学习者和工作台状态。
- 工作台状态必须包含 `courseId` 且等于 `ai-intro`；若课程不匹配则重置工作台状态。
- 刷新资源工作室时读取 `latestRunId` 对应的后端快照。
- 刷新首页时根据持久化状态重新渲染状态栏和下一步。
- 后端返回 404 时清理失效的 `latestRunId` 并提示重新生成。

## 9. 错误与边界

- 切换学生必须清理全部工作台状态，不保留上一学生的资源、路径或分数。
- 前一步 API 失败时不得错误推进状态。
- 资源 partial 只能显示“部分完成”，不能视为六类资源全部成功。
- 评估失败不得覆盖历史得分。
- 所有可点击状态胶囊和下一步按钮都必须有可见加载、错误或跳转反馈。

## 10. 测试策略

### 单元测试

- 下一步状态推导覆盖无学习者、画像不足、无资源、生成中、失败、完成、路径完成和已评估。
- 工作台状态持久化和损坏 JSON 回退。
- 学生切换清理状态。

### 组件测试

- 首页在无学生/有学生时显示不同内容。
- 状态栏展示状态并触发对应页面回调。
- 资源数量与 partial 状态显示正确。
- 评估分数更新状态栏。

### 浏览器端到端

- 选择学生后出现全局状态栏。
- 画像 → 资源 → 路径 → 辅导 → 评估主流程持续更新状态。
- 每个下一步按钮跳转正确。
- 刷新后资源数量、路径状态和评估分数恢复。
- 自由跳转到任意侧边页面均保留当前主题和状态。
- 切换学生后工作台回到选人状态，旧状态不残留。

## 11. 非目标

- 不新增教师端、班级管理或账号系统。
- 不更改画像抽取、知识库检索、多智能体编排和后端数据模型。
- 不把自由工作台改造成不可跳步的向导。
- 不改变现有六类资源生成逻辑。

## 12. 验收标准

- 任意页面都能看到同一课程、主题和闭环状态。
- 用户无需记忆刚才完成了什么。
- 首页在已有学生时提供可继续的工作台，而不是重新选人。
- 每个阶段的下一步都有唯一明确入口。
- 刷新页面不会让已完成状态看起来全部丢失。
- 自由导航、错误反馈、资源下载和原有完整流程继续通过测试。
